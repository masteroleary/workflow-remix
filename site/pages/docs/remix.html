Remixing a file

Remix turns a workflow into a form, fills it from the file you opened, and queues what you changed on your ComfyUI.

The same form appears in two places: the Remix page raised from the bar under any tile (or from the viewer), and the inspect page of a file. They are one form, so anything that works in one works in the other.

The Remix page goes in three steps, as tabs: Workflow (which workflow and its form), Keywords (the prompt replacements) and Run. Next walks through them, and skips Keywords when the prompt has no [keyword] in it. Back, Esc or the browser's back button returns you to wherever you raised it from.

Which workflow runs

The workflow card at the top opens a menu of:

  • Inherit (this file), the exact workflow written into the file.
  • The workflows in your library, with the file's own prompt carried into them. This is how a picture made one way is sent through a different model, a detailer pass or an image-to-video workflow.
  • Shortcuts, a workflow saved together with the values on screen (Save shortcut), listed under the workflow they belong to.

Every workflow carries a prompt of its own, so switching asks which one you want to keep: the one in the box, or the new workflow's. A shortcut never asks, because its prompt is what was saved.

The form

WorkflowRemix reads the graph and works out which of its settings are worth a control: the prompt, the seed, steps and guidance, the size, the models and LoRAs it loads, the images it takes in. The controls are grouped the way the graph is.

What it found and left out sits in the hidden fields list, where you can switch a field on. A setting that cannot reach the render, because its node is not wired to an output, is not offered at all: a control that changes nothing is worse than no control.

Seed

The seed box states what will be used, or nothing.

  • Empty (it reads random, 🎲) means a fresh seed for every run.
  • Pinned (📌) means exactly the number in the box.
  • ↺ this file's seed puts back the seed the opened file was made with, and pins it. With the same seed and nothing else changed, you get the same picture again.

Models

A model field is a search box whose results are pills beside it. The first model you pick replaces the one the form arrived with; every pick after that adds one. A run is then queued once per picked model.

  • Runs go to ComfyUI model by model, so each checkpoint is loaded once and not swapped between every render.
  • All the models share the same seeds. What differs between the results is the model.
  • A pill in amber names a model your ComfyUI does not list. That run would fail at the loader.
  • Picking models from different families puts a line under the pills: the LoRAs, VAE and text encoder in the form were set up for one of them.

LoRAs

At the foot of every LoRA stack is the same search box, over your whole LoRA library as ComfyUI lists it. Pick one to add it, or to switch a row back on. A high-noise and low-noise pair counts as one LoRA: adding it to one stack adds its partner to the other.

Size, and Match Input Image

A workflow that takes an image in and also has a width and height is stating its frame twice. Match Input Image appears under the size fields, starts ticked, and sizes each run to the image going in. Untick it to type a size yourself.

Image inputs

A workflow's main image (its loader titled MAIN IMAGE) is the file you are remixing, and the image box says so: it shows that file, not the picture the workflow was saved with. An image field has Browse, which opens your library to pick something else; pick several and each becomes a job of its own. Some workflows have an optional second image, a reference say. It arrives empty, and choosing an image is what switches that branch of the workflow on for the run.

Keyword Prompt or Remix Prompt

If the file was made from a prompt with [keywords] in it, the file holds that prompt twice: as you typed it, and as it ran once the keywords were answered. A switch above the prompt field offers both. Keyword Prompt gives you the template, to be answered afresh; Remix Prompt gives you the finished text, to edit by hand.

Running

The Run tab holds the run count and the button, which says how many jobs one press queues (Run · 3 jobs); the Prompt Replacements panel's summary line states the same number. On the inspect page the panel sits at the foot of its Run tab. The count is:

models picked  ×  files picked  ×  prompt variations ticked

Each job renders the run count you set. Outputs arrive as thumbnails as each one finishes, with favourite and delete on them, and every job is listed on the Jobs page whether or not you stay on this one.

ComfyUI has to be running. If it is not, the app says so and, where it can find ComfyUI's launcher, offers to start it.

Every run is checked first

Before a run reaches ComfyUI it is read by the built-in safeguard, which refuses a run that describes a minor sexually and adds a short set of words to the negative prompt of every other run. So the negative prompt a file records can hold a few words more than you typed. How the safeguard works.

Making a change stick

Anything you type lasts for the visit: opening one of the results in the viewer and coming back keeps it, while leaving for another page starts again from the file. To keep it for good, it depends what you want kept.
