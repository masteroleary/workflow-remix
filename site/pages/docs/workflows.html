Workflows

The Workflows page is the library Remix runs from: every workflow saved in your ComfyUI, with a switch for whether the app offers it.

The library

WorkflowRemix reads the workflows folder of the ComfyUI you pointed it at. Nothing is copied or renamed. For each workflow you can:

  • Switch it on, so it appears in Remix's drop-down.
  • Give it a label, the name it goes by in the app.
  • Open it on the inspect page with no file behind it, to see and edit its form.
  • Correct its roles with Roles (below).

Those choices are kept by the app, beside your other settings. Your workflow files are left as they are.

Each card also says what the workflow makes, read off its graph: T2I (text to image), I2I (image to image), T2V, I2V and V2V for video, and …2A for audio. A workflow whose output the app does not recognise gets a plain graph icon.

Checking a workflow, then running it

A workflow that has not been checked yet wears an Enable button over its card. Press it and the app works out everything the workflow needs (every custom node, checkpoint, LoRA, VAE and text encoder) and ticks each one off in turn, ✓ found or ✗ missing.

  • Everything found. The workflow is marked as checked, the button goes, and a big Run appears. It runs the workflow once on its own settings and takes you to Jobs to watch. Where a starter workflow takes a picture, Run feeds it one of the sample pictures a new install comes with, all but Krea Image Edit by Reference, which needs two pictures of your own.
  • Something missing. The sheet lists the missing custom nodes, and the missing files grouped by the folder each belongs in under ComfyUI/models. Copy details copies that list as plain text with what to do about it: install the nodes through ComfyUI-Manager, put the files in those folders, restart ComfyUI and check again.
  • ComfyUI not running. Which nodes exist can only be asked of ComfyUI, so the sheet says to start it rather than reporting everything as missing.

A file counts as installed if ComfyUI lists it or if it is on disk in your ComfyUI's models folder, so a Docker install with models mounted elsewhere and a local one with files not yet loaded both come out right. The check reads only; it installs and downloads nothing.

The app runs ComfyUI's copy

A run always uses the workflow file in your ComfyUI folder as it is now. Edit a workflow in ComfyUI and save it, and the next remix uses the new version.

How a form is made

There is nothing to map by hand. The app reads the graph, asks ComfyUI what each node's settings are, and decides which are worth a control and what kind: a prompt box, a seed, a slider, a model picker, a LoRA stack, an image picker. It follows the wiring, so it knows which settings can reach the output and offers only those.

Three things it also works out:

  • Muted and bypassed nodes. Their settings are listed as asleep in the hidden fields, and stay available: a style preset may wake them.
  • Optional image inputs. A bypassed image loader that feeds the render is offered as an empty picker. Choosing an image switches its branch on for that run.
  • Edit-instruction workflows. A workflow can declare that its prompt is an instruction for the image going in (“make the jacket red”) and not a description. Such a workflow keeps its own prompt when you switch to it.

Correcting it

Detection is usually right, and when it is not, three controls change the answer for good.

ControlUse it whenWrites
RolesThe wrong field was taken for the prompt, seed, steps or guidance.The app's settings.
Save field setupYou want different fields shown, or different names on them.The app's settings.
Update workflowYou want the values on screen to be the workflow's new defaults.The workflow's own .json, after a one-time .bak.

Only the values a run would have set are written. The rest of the graph is left exactly as it was.

A workflow from a file

Any file that carries a workflow can give it back: the workflow inside it can be saved into your ComfyUI workflows folder as a new one, and then switched on like any other. If the app recognises a file's workflow as one that is in your ComfyUI but not switched on, it says so and offers to add it.

Starter workflows

A new install copies five example workflows into your ComfyUI workflows folder and switches them on. They are a starting point: they name custom nodes and models you may need to install or swap for your own, which is what Enable is for. The starter workflows lists what each one does and needs.

Putting the starters back

Settings → Restore defaults puts back what a new install starts with, part by part: Overwrite keywords, Overwrite prompts and Overwrite workflows, none ticked to begin with, and the app asks before it writes anything.

  • A starter workflow you changed is kept beside itself as <name>.bak before the shipped one goes back. Your own workflows and shortcuts are left alone.
  • The keywords and the prompt library are replaced as shipped, and no copy is kept, so that part cannot be undone.
  • Only from the computer the app runs on, not from a phone.
